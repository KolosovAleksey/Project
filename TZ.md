# Техническое задание — Команда 3
## «Портал учёта мероприятий»

### 1. Назначение и цель
Веб-портал для публикации мероприятий и записи участников. Решает задачу хаотичной регистрации «в чатах»: даёт каталог событий, запись с контролем числа мест и учёт участников.

### 2. Состав команды и роли
| Участник | Роль | Ответственность |
|---|---|---|
| Окороков Богдан | Team Lead / Frontend (Views) | Razor-вёрстка, layout и навигация, стили, сборка, координация |
| Колосов Алексей | Backend | Модели и EF Core, бизнес-логика записи с контролем мест, аутентификация и роли |
| Попов Артём | Backend (изолированные модули) | CRUD справочников, формы и валидация отдельных страниц, тестовые данные, ручное тестирование |

### 3. Технологический стек
- **Платформа:** ASP.NET Core MVC (C#)
- **ORM:** Entity Framework Core
- **БД:** SQLite (разработка), опционально SQL Server
- **Frontend:** Razor Views, Bootstrap
- **Инфраструктура:** Git

### 4. Роли пользователей
- **Гость** — просмотр каталога мероприятий.
- **Участник** — запись на мероприятие, просмотр и отмена своих записей.
- **Администратор (организатор)** — CRUD мероприятий, просмотр списков участников.

### 5. Функциональные требования

**5.1 Аутентификация (обязательно)**
- Регистрация, вход, выход (можно на ASP.NET Core Identity или собственная реализация).
- Роли «участник» и «администратор».

**5.2 Каталог мероприятий (обязательно)**
- Список мероприятий с фильтром по категории и статусу.
- Карточка мероприятия: название, категория, площадка, дата и время, число мест, описание, количество свободных мест.

**5.3 Запись на мероприятие (обязательно, ключевая логика)**
- Кнопка «Записаться» для авторизованного участника.
- **Контроль лимита мест:** при достижении вместимости запись блокируется («мест нет»).
- Повторная запись на одно мероприятие запрещена.
- Запрет записи на завершённое мероприятие.

**5.4 Личный кабинет (обязательно)**
- Список «Мои мероприятия» со статусами записи.
- Отмена записи (освобождает место).

**5.5 Администрирование (обязательно)**
- CRUD мероприятий.
- Просмотр списка участников каждого мероприятия.

**5.6 Дополнительно (stretch)**
- Статусы мероприятий (анонс / идёт / завершено) с автопереходом по дате.
- Поиск по названию.
- Экспорт списка участников в CSV.
- Статистика: число записей по мероприятиям и категориям.

### 6. Модель данных (минимум)
- **User**(id, full_name, email, password_hash, role)
- **Category**(id, name)
- **Venue**(id, name, address, capacity)
- **Event**(id, title, category_id → Category, venue_id → Venue, start_datetime, end_datetime, capacity, status, description)
  - status ∈ {announced, ongoing, completed}
- **Registration**(id, event_id → Event, user_id → User, registered_at, status)
  - status ∈ {confirmed, cancelled, attended}

### 7. Экраны (Razor Views, ориентир)
| Экран | Назначение |
|---|---|
| /Events | Каталог с фильтром |
| /Events/Details/{id} | Карточка мероприятия + кнопка записи |
| /Account/Register, /Account/Login | Регистрация и вход |
| /My/Events | Мои записи |
| /Admin/Events | Управление мероприятиями (CRUD) |
| /Admin/Events/{id}/Participants | Список участников |

### 8. Исходные данные
- `categories.csv` — 5 категорий.
- `venues.csv` — 5 площадок.
- `users.csv` — 10 пользователей (2 админа).
- `events.csv` — 8 мероприятий разных статусов.
- `registrations.csv` — 15 записей с разными статусами.

### 9. Контрольные тест-сценарии (для приёмки)
1. Регистрация → вход → запись на мероприятие со свободными местами — успех, счётчик свободных мест уменьшается.
2. Запись на мероприятие, где места закончились, — **заблокирована** с сообщением.
3. Повторная запись на то же мероприятие — отклонена.
4. Запись на завершённое мероприятие — отклонена.
5. Отмена записи освобождает место (счётчик растёт, можно записаться снова).
6. Администратор создаёт/редактирует/удаляет мероприятие.
7. Администратор видит корректный список участников мероприятия.
